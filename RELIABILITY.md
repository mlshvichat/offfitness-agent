# Повторные попытки и запас постов

Слоты публикаций остаются 09:00,14:00,19:00 Europe/Moscow.
Каждые 15 минут GitHub Actions проверяет журнал доставок обоих каналов.
Пропущенные слоты начиная с вечера 3 ноября сохраняются и на следующих днях:
ограничение прежней схемы в два часа больше не удаляет попытку.
За один запуск догоняется максимум два слота, чтобы не отправлять весь накопленный
за простой объём разом. Запуски сериализованы общей очередью GitHub Actions.

У каждого канала отдельный запас из шести заранее одобренных вечнозелёных текстов.
Это целевой размер, а не обещание, что очередь уже заполнена. На каждом запуске
готовится максимум два запасных текста. При отсутствии запаса для просроченного
слота выполняются до трёх новых попыток генерации. Каждый текст проходит весь
редакторский цикл, включая безопасность, достоверность и до трёх правок.
Отклонённые тексты не публикуются. Следующий запуск снова ищет подходящий вариант.

Одобренный текст связывается с отчётом и SHA-256 точного содержимого.
Перед отправкой проверяются неизменность и повтор относительно последних постов.
Одобрение сохраняется в GitHub до использования: сбой модели в момент отправки
не мешает использовать уже проверенный запас. При новом планировании учитываются
и история доставок, и ещё не использованные тексты.

При 503/429 предусмотрены две модели Gemini. Для ошибки 503 модель выключается
на пять минут, для 429 на час. Паузы сохраняются между запусками, поэтому система
не продолжает бессмысленно расходовать квоту в одном бесконечном процессе.
Работа возобновляется при очередном пробуждении, пока слот не получит подтверждение.
Ошибки публикуются как неуспешные запуски Actions; очередь и замечания сохраняются
во внутренних артефактах, не в Telegram.

Резервирование и запись об отправке сохраняются до/после sendMessage соответственно.
Явный отказ Telegram (включая HTTP 429) возвращает текст в запас для новой попытки.
Неопределённый ответ сети нельзя слепо повторять: сообщение могло быть доставлено.
Система пробует подтвердить его по точному тексту и более новому ID публичного
канала. При невозможности подтвердить доставку нужна ручная сверка, а не дубль.
Это ограничение Telegram Bot API без ключа идемпотентности.

Ни GitHub Actions, ни Gemini, ни Telegram не гарантируют непрерывную доступность.
При полном простое всех провайдеров и пустом запасе публикация может задержаться.
Изменение устраняет потерю слота после единственной ошибки, но не гарантирует
выход строго до секунды. Запас нужно наблюдать в data/fitness-queue.json и
data/auto-queue.json: remaining_due показывает очередь пропущенных выпусков.
